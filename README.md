# SPRT-chart — график смен

Веб-клиент для просмотра и редактирования графика смен. Данные хранятся в Pyrus,
запросы идут через бэкенд: сейчас это n8n, позже будет сервис в Docker.

Проект сделан на основе логики `chart-PosService`, только график смен (без модуля клиентов).

## Как устроено

```
Браузер (этот репозиторий)
   │  POST {api.baseUrl}  { action, payload }  + Bearer-сессия
   ▼
Бэкенд: n8n (сейчас) → Docker (потом)     ← секреты Pyrus/Mango только здесь
   │
   ├─ Pyrus API  (формы «График работы», «График отпусков», справочники)
   └─ Mango Office API  (отправка кода входа)
```

- Фронт знает **один** адрес — `config.json → api.baseUrl`. Все действия описаны в
  [`docs/API_CONTRACT.md`](docs/API_CONTRACT.md): `auth.start`, `auth.verify`, `auth.me`,
  `auth.logout`, `pyrus.request`, `schedule.save`.
- Код входа генерирует и проверяет **только бэкенд**. Права при сохранении тоже проверяет бэкенд.
- Все ID Pyrus лежат в `config.json`, в коде их нет.

## Настройки компании (`config.json`)

| Что | Значение |
|---|---|
| Форма «График работы» | `2470373`, поля: подразделение 1, сотрудник 2, дата/время 3, деньги 4, смена 5 |
| Форма «График отпусков» | `2470368`, поля: период 1, год 2, отпускник 3, отдел 4, дней 5 |
| Справочник «Смены работы» | `309671` |
| Справочник «Подразделения компании» | `309670` (ТП, ПО) |
| Редактор графика ТП | роль `1329637` |
| Редактор графика ПО | роль `1329638` |
| Часовой пояс | UTC+4 (`timezone.localOffsetMin: 240`) |

Вкладки задаются в `config.lines`. Новое подразделение — это новая запись:

```json
{ "key": "OP", "label": "ОП", "departmentName": "ОП", "editRoles": [123], "orgDepartmentIds": [] }
```

- `departmentName` — как элемент называется в справочнике `309670`. Его `item_id` подтягивается сам,
  но можно указать явно в `departmentItemId`.
- `orgDepartmentIds` — отделы оргструктуры Pyrus. Их сотрудники всегда видны во вкладке,
  даже без смен. Кроме них во вкладку попадают все, у кого есть смены этого подразделения в месяце.
- `editRoles` — роли Pyrus, которым можно редактировать вкладку. `auth.permissions.editAll` —
  роли, которые редактируют всё.
- Вкладка «ВСЕ» только для просмотра: у каждой смены должно быть подразделение.

Колонки справочника смен ищутся по названиям («Название смены», «время смены», «Сумма за смену»,
«Подразделение»). Если в справочнике они называются иначе, укажи их в `pyrus.catalogColumns.shifts`.
Колонка подразделения может содержать «ТП, ПО» или «ВСЕ». Если колонки нет, смена доступна везде.

## Локальный запуск (с мок-бэкендом)

```bash
node dev/mock-server.mjs
# открыть http://localhost:8787 — телефон 79000000001 (редактор ТП) или 79000000003 (редактор ПО), код 123456
```

Мок реализует тот же контракт на фейковых данных и печатает в консоль, что пришло в `schedule.save`.

## Деплой фронта

Это статика (HTML + ES-модули), сборка не нужна. Подойдёт любой хостинг: GitHub Pages, nginx.
Перед деплоем пропиши в `config.json` реальный `api.baseUrl`.

## Структура

```
index.html, css/styles.css
config.json                 — настройки компании
js/app.js                   — UI и логика графика
js/config.js                — загрузка и нормализация config.json
js/api/apiClient.js         — единственная точка сетевого обмена (action + payload)
js/api/pyrusClient.js       — чтение Pyrus через action "pyrus.request"
js/services/*.js            — сотрудники, справочники, график, отпуска, производственный календарь
js/cache/requestCache.js    — TTL-кеш + дедупликация запросов
dev/mock-server.mjs         — мок бэкенда для локальной разработки
docs/API_CONTRACT.md        — контракт API (его реализуют n8n и будущий Docker-сервис)
```
