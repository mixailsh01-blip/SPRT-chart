# SPRT-chart

График смен, обмены, отпуска и обеды. Node.js обслуживает интерфейс и API на одном домене. Смены, отпуска и сотрудники хранятся в Pyrus. Локальные сессии, параметры телефонии и обеды хранятся в SQLite.

## Запуск на сервере

\`\`\`bash
git clone --branch codex/docker-portal https://github.com/mixailsh01-blip/SPRT-chart.git sprt-chart
cd sprt-chart
install -m 600 .env.example .env
nano .env
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8787/healthz
docker compose logs --tail=100 portal
\`\`\`

В \`.env\` укажите \`PYRUS_LOGIN\` и \`PYRUS_SECURITY_KEY\` бота из узла «Pyrus: токен», настройки SMTP и адрес \`SMTP_FROM\`. Для TLS при подключении SMTP на порту 465 задайте \`SMTP_SECURE=true\`, для STARTTLS на 587 оставьте \`false\`. Укажите получателей \`LUNCH_ALERT_EMAIL\` и \`MANGO_ALERT_EMAIL\`. Для Mango заполните \`MANGO_API_KEY\` и \`MANGO_API_SALT\` из настроек интеграции.

Направьте существующий HTTPS-прокси для \`portal.sprt-service.ru\` на \`http://127.0.0.1:8787\`. Пример для Nginx внутри существующего блока \`server\`:

\`\`\`nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
\`\`\`

После проверки конфига перезагрузите Nginx командой \`sudo nginx -t && sudo systemctl reload nginx\`. Проверьте \`curl -fsS https://portal.sprt-service.ru/healthz\` . Перед проверкой входа остановите старый опрос «SPRT: повторная отправка доступа» в n8n, чтобы он не подхватил новые уведомления о входе. В форме Pyrus «Уведомления сотрудникам» обновите адрес кнопки «Войти в график» на \`https://portal.sprt-service.ru/?li=\${password}\`, где \`password\` — текущая переменная поля 9.

## Переключение Mango

Сервис стартует с отключённой записью в Mango. SQLite создаётся с нуля, пользователи входят повторно. При первой синхронизации смены подтягиваются из Pyrus. Для смен без локальной записи телефония включена по умолчанию, а длительность берётся из Pyrus или шаблона смены. Перед переключением проверьте исключения и длительность нестандартных смен.

Когда проверите график, остановите старые задачи n8n, которые записывают в Mango. Задайте \`MANGO_WRITE_ENABLED=true\` в \`.env\` и примените настройки командой \`docker compose up -d\`.

## Уведомления

Портал отправляет код входа по SMTP и создаёт уведомление в Pyrus. Об аварийном составе Mango и обменах сменами сервис сообщает по почте. Просроченный обед остаётся открытым до нажатия «В линию». Сотрудник и руководитель получают уведомление о просрочке в Pyrus. Если задан `LUNCH_ALERT_EMAIL`, руководитель также получает письмо. Чтобы опрашивать Pyrus для повторной выдачи доступа, включите \`PYRUS_RESEND_ENABLED=true\` после отключения прежней задачи n8n. Первый опрос отмечает существующие заявки обработанными. Новую заявку создавайте после первого опроса.

SQLite сохраняется в именованном томе \`sqlite\` при пересоздании контейнера. Команда \`docker compose down -v\` удаляет этот том.

## Настройки компании (`config.json`)

| Что | Значение |
|---|---|
| Форма «График работы» | `2470373`, поля: подразделение 1, сотрудник 2, дата/время 3, деньги 4, смена 5 |
| Форма «График отпусков» | `2470368`, поля: период 1, год 2, отпускник 3, отдел 4, дней 5 |
| Справочник «Смены работы» | `309671` |
| Справочник «Подразделения компании» | `309670` (ТП, ПО) |
| Редактор графика ТП | роль `1329637` |
| Редактор графика ПО | роль `1329638` |
| Часовой пояс | UTC+4 (`timezone.localOffsetMin: 240`) |

Вкладки интерфейса задаются в `config.lines`. Новое подразделение — это новая запись:

```json
{ "key": "OP", "label": "ОП", "departmentName": "ОП", "editRoles": [123], "orgDepartmentIds": [] }
```

- `departmentName` — как элемент называется в справочнике `309670`. Его `item_id` подтягивается сам,
  но можно указать явно в `departmentItemId`.
- `orgDepartmentIds` — отделы оргструктуры Pyrus. Их сотрудники всегда видны во вкладке,
  даже без смен. Кроме них во вкладку попадают все, у кого есть смены этого подразделения в месяце.
- `editRoles` — роли Pyrus, которым можно редактировать вкладку. `auth.permissions.editAll` —
  роли, которые редактируют всё.
- Роль Pyrus `1331872` разрешает редактировать смены во вкладке «ВСЕ» у сотрудников вне ТП. Новые смены получают подразделение по карточке сотрудника или последней смене с известным подразделением. Эта же роль позволяет добавлять и удалять отпуска всех сотрудников, а также менять их даты в карточке отпуска.

Колонки справочника смен ищутся по названиям («Название смены», «время смены», «Сумма за смену»,
«Подразделение»). Если в справочнике они называются иначе, укажи их в `pyrus.catalogColumns.shifts`.
Колонка подразделения может содержать «ТП, ПО» или «ВСЕ». Если колонки нет, смена доступна везде.

## Локальный запуск (с мок-бэкендом)

```bash
node dev/mock-server.mjs
# открыть http://localhost:8787 — телефон 79000000001 (редактор ТП) или 79000000003 (редактор ПО), код 123456
# LUNCH_MIN=1 node dev/mock-server.mjs — обед на 1 минуту, чтобы проверить просрочку и ручной возврат
```

Мок реализует тот же контракт на фейковых данных и печатает в консоль, что пришло в `schedule.save`.
